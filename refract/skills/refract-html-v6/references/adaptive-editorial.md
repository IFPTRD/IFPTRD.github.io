# Adaptive editorial patterns — examples, not mandatory templates

Choose a pattern based on the **reader's actual goal**. The same document may combine patterns. Do not force these section names or layouts.

| Reader's need | Likely organizing pattern | Suitable Refract blocks | Common mistake to avoid |
| --- | --- | --- | --- |
| Learn an unfamiliar subject | Concepts → key distinctions → practical application → reference | paragraph, cards, table, glossary | Converting every paragraph into flash cards |
| Follow an SOP or operating procedure | Prerequisites → exact steps → decision points → exceptions → verification | steps, checks, note, table | Omitting prerequisites or treating mandatory exceptions as optional |
| Understand regulations or policy | Scope/applicability → requirements → responsibilities → exceptions → reference | paragraph, table, bullets, note, resources | Inventing legal interpretations or simplifying away conditions |
| Start a role or onboard a team | First actions → systems/resources → workflows → definitions | steps, cards, resources, glossary | Copying an HR handbook's chapter order regardless of use |
| Consult a technical reference | Concepts → parameters/options → examples → troubleshooting → links | table, paragraph, note, resources | Replacing precise values with vague summaries |
| Resolve problems | Recognize symptoms → likely causes supported by source → resolution → escalation | steps, table, note | Inventing diagnostic logic or fixes not in source |
| Make informed decisions | Situation → factors/options → consequences/ownership → next steps | table, checks, cards, note | Creating performative checklists and unsupported decision rules |
| Study or teach | Learning path → core concepts → examples → summary/terms | paragraph, steps, cards, glossary | Pretending to provide a live quiz without executable support |
| Understand project or event | Purpose → milestones → responsibilities → status → resources | timeline (if grounded), table, cards | Fabricating dates or filling a timeline with nonchronological items |
| Navigate a large collection | Topic/task index → concise descriptions → direct links/definitions | cards, resources, glossary, tables | Turning every link into a separate page |
| Support an executive during an exercise | Role → decision aid → governance/partners → incident stages → reference | checks, cards, governance (if grounded), timeline (if grounded) | Applying executive framing to unrelated documents |

## A short quality-control example

A source has nine repetitive paragraphs describing how different staff submit a request. A useful guide might combine them into a supported five-step procedure, a small "who approves what" table, and a separate exception note. **Only do so if the source supports that grouping and order.**

A source contains long narrative explaining the history of a subject, with no operational procedure. Create a clear conceptual guide. **Do not invent steps, owners, escalation routes or checklists to make it resemble a playbook.**

A source contains complex technical drawings or screenshot-based instructions. Summarize supported aspects but do not claim those visuals were preserved or reconstructed. If visually exact material is essential, retain it as an external approved asset during editorial review.

## Information design principles

1. Each page should earn its place. Avoid one-page-per-source-heading, but do not over-consolidate different reader tasks.
2. Make titles specific enough that navigation works without reading every intro.
3. Be economical with hero banners and highlight boxes. Emphasize only material that deserves attention.
4. Use a table only if scanning rows/columns beats prose; use a diagram only if it communicates relationships better and is factual.
5. Keep original words for legally or technically significant concepts; clarify in glossaries rather than altering definitions.
6. Don't add provenance or publishing boilerplate unless explicitly requested.
7. Deliver content suitable for the actual reader, not an imagined generic decision-maker.
